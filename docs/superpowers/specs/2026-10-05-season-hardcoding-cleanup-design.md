# 화면의 시즌 하드코딩 정리(2027 대비) 설계

- 작성: 2026-10-05, bstats 화면 세션
- 근거: DB 세션 2027 대비 보고서 5장(dashboard_js 목록, HIGH 3·MED 3·LOW 7)
- 결정: evan (진행 중 = 정규시즌 끝날 때까지, 판단은 화면에서, 범위는 전부 한 번에)
- 상태: 설계 승인됨(evan).

## 1. 왜

화면 여러 곳이 "기록이 있는 가장 최근 시즌 = 진행 중 시즌"으로 보고, 몇 곳은 연도를 글자로 박아 두었습니다. 그래서 다음 일이 생깁니다.

- 2027 개막일에 KBO 실시간 순위(2027)가 기록이 아직 2026인 표에 붙습니다(팀·선수 통계).
- 2026 포스트시즌이 시작된 뒤에도, 비시즌 내내 끝난 2026을 '진행 중'으로 표시합니다(팀·선수·요인 통계).
- 요인 통계는 "2026은 진행 중 시즌" 문장과 `season >= 2026` 배지가 글자로 박혀 있습니다.
- 요인 통계 RE24 표는 500행만 받아 2028에 잘립니다. 참조 표(순위표 373행)도 몇 년 뒤 같은 일을 겪습니다.
- 시즌 목록을 못 받으면 브라우저 연도부터 목록을 만들어 1~3월에는 빈 시즌이 기본이 됩니다.
- 그 밖에 낡은 기본값(season = 2025), 9월 30일 고정, 아티클 기본 시즌·문구, 캐시 유효기간 없음, 홈 일정 문구가 있습니다.

## 2. 진행 중 판단

- 뜻: **정규시즌이 끝날 때까지** 진행 중입니다. 그해 포스트시즌 첫 경기가 들어오면 끝난 시즌입니다(정규시즌 기록은 그때부터 바뀌지 않음).
- 규칙: 시즌 Y 는 (Y = 한국 시각 올해) 이고 (Y 의 가장 최근 경기가 '정규시즌') 이면 진행 중입니다.
- 실시간 순위(/standings)는 진행 중인 시즌에만 씁니다. 그래서 개막일에 끝난 2026 에 2027 순위가 붙지 않습니다. DB 세션이 제안한 /standings 시즌 필드는 이번에 쓰지 않습니다(API 변경 없음).
- 판단은 화면에서 합니다. API·Worker 는 바꾸지 않습니다.

## 3. 공용 모듈 `dashboard_js/js/stats/season.js` (새)

- `kstToday(now?)`: 한국 시각 오늘 { y, m, d, iso: 'YYYY-MM-DD' }.
- `isLive(season, state)`(순수): state = { kstYear, lastGame }. season === kstYear 이고 lastGame 이 그 시즌의 '정규시즌' 경기면 true.
- `summarize(season, games, kstYear)`(순수): `/games` 응답(최신순)에서 { live, lastGame, lastRegularDate, firstDate } 를 만듭니다.
  - lastRegularDate: 목록에서 처음 나오는 '정규시즌' 경기 날짜(포스트시즌은 많아야 20경기쯤).
  - firstDate: 받은 경기가 80개보다 적으면 가장 이른 날짜, 아니면 null(시즌이 이미 2주 넘게 지남).
- `loadSeasonState(base, season)`(브라우저): `/games?season=Y&limit=80` 한 번. 실패하면 { live: season === kstYear, failed: true, error } (지금 동작과 같음).

## 4. 공용 데이터 `dashboard_js/js/stats/data.js`

- `loadSeasons` 실패 시 대체 목록: 한국 시각 올해부터(4월 전이면 작년부터) 1982 까지.
- 저장 캐시(sessionStorage) 시즌 목록·참조 표에 6시간 유효기간. 키 버전을 올립니다.
- `loadRefs` 참조 표: `/db/table/<표>?limit=500&offset=N` 로 끝까지 이어 받습니다. 중간에 실패하면 그 표는 실패로 알립니다(반쪽 표를 쓰지 않음).

## 6. 오류

- 진행 중 판단 실패: "올해면 진행 중"으로 보고, 팀·선수 통계는 알림 줄에 "진행 중 여부를 확인하지 못해 올해 시즌을 진행 중으로 봅니다"를 띄웁니다. 요인 통계·아티클·홈은 콘솔에만 남깁니다.
- 시즌 목록 실패: 지금처럼 알림 + §4 대체 목록.
- 이어 받기 중간 실패: 그 표 전체를 실패로 알림.

## 7. 검증

- Node(저장소 밖): season.js(정규시즌 중·포스트시즌 시작 뒤·해 바뀐 비시즌·받기 실패·시즌 초반 첫 경기·마지막 정규시즌 날짜), data.js(KST 대체 목록·캐시 유효기간·이어 받기, 가짜 fetch), 글자 검사(세 페이지가 season.js 를 싣는지, factor-stats 에 '2026' 없음, api.js 에 `season = 2025` 없음, 아티클 새 문구).
- 캡처(127.0.0.2, 바탕화면 `bstats_미리보기/season_cleanup/`): 팀·선수 통계 2026(오늘은 진행 중)·2025(끝난 시즌), 요인 통계, 아티클, 홈, 휴대폰. 포스트시즌이 시작되면 운영에서 저절로 바뀌는지 한 번 더 봅니다.
- 페이지 API 호출이 바뀌므로 `py scripts/build_lineage.py` → `py -m pytest tests`.

push·Pages 배포는 evan 허락 뒤(각각). 배포 전 선수 분석 세션과 맞춥니다.
