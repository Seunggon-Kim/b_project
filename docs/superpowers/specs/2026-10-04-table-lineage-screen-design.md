# 테이블 계보 탭 화면 설계

- 작성: 2026-10-04, bstats 화면 세션
- 대상 화면: `dashboard_js/pages/database-explorer.html` 의 새 탭 **테이블 계보** (`#lineage`)
- 앞선 설계: `2026-10-04-table-lineage-design.md`(목적·데이터 세 조각·상태 점 규칙, DB 세션). 데이터 계획: `docs/superpowers/plans/2026-10-04-table-lineage-data.md`
- 데이터: `dashboard_js/data/table_lineage.json`(DB 세션 생성물, 화면 세션은 읽기만), `/db/tables`(행 수), `/jobs/status`(실행 기록)
- 상태: 설계 승인됨(evan).

## 1. 목적

1. 방문자: 숫자가 어디서 왔는지 수집부터 화면까지 한 장으로 보여 줍니다.
2. 운영: 멈춘 표·실패한 작업을 바로 찾습니다(2026-10-03 `team_season_rank` 가 한 달 넘게 멈춰 있던 일 같은 것).

## 2. 화면 구성

- 탭: 데이터 탐색 페이지의 세 번째 탭 "테이블 계보". 주소 `#lineage` 로 바로 열립니다. 기존 "데이터 탐색"·"사이트맵" 탭은 그대로입니다. 탭을 처음 열 때 데이터를 받습니다.
- 요약 줄(그림 위): "정상 N · 실패 N · 오래됨 N · 기록 없음 N · 손 작업 11". 숫자(손 작업 제외)를 누르면 그 상태의 표만 진하게, 나머지는 흐리게 합니다. 같은 숫자를 다시 누르면 풀립니다. 안내 한 줄: "선을 따라가면 숫자가 어디서 왔는지 보입니다. 상자를 누르면 이어진 경로만 진하게 보입니다."
- 그림: 5칸 고정
  1. 원천(7)
  2. 수집 작업(4: daily·roster·weekly·monthly, 실행 시각 함께)
  3. 표 — 받아 온 표(10) + 접힌 상자 "손 작업 표 11개"(누르면 펼침·다시 누르면 접음)
  4. 계산 표(6)
  5. 화면(7)
  - 숨김: `kind: meta` 표 3개, `explorer: true` 페이지(데이터 탐색 자신, 모든 표를 읽어 선이 없음).
  - 표 상자 이름은 영문 표 이름(`games`, `play_by_play`)입니다. 한국어 설명은 상자에 마우스를 올리면(`title`) 보이고 상세 카드에 나옵니다. 화면 상자는 페이지 제목에서 " - Bstats" 꼬리를 뗀 이름입니다.
  - 선: SVG 곡선. 처음에는 모두 옅은 회색. `source:kbo_live → page:` 선은 가운데 칸을 건너 그대로 잇습니다.
  - 손 작업 표가 접혀 있으면 그 표들에서 나가는 선을 "손 작업 표" 상자 하나에서 나가는 선으로 모읍니다(같은 화면으로 가는 선은 하나로).
- 누르기: 상자를 누르면 그 상자에서 선을 따라 앞으로 끝까지·뒤로 끝까지 이어진 상자와 선만 진하게, 나머지는 흐리게 합니다. 같은 상자를 다시 누르거나 그림의 빈 곳을 누르면 처음으로 돌아갑니다. 요약 줄 강조와 상자 강조는 하나만 켜집니다(나중에 누른 것).
- 상태 점: 표 상자(손 작업 표 제외)와 수집 작업 상자에 점(초록·빨강·회색). 손 작업 표는 점 대신 "손 작업" 표시. 점에 `data-tooltip` 으로 기준을 적습니다(4장).
- 상세 카드(그림 바로 아래): 아무것도 누르지 않았을 때는 숨깁니다.
  - 표: 설명·분류, 행 수(`/db/tables`), 종류(받아 온 표·계산 표·손 작업 표), 쓰는 스크립트와 그 작업·실행 시각·마지막 결과, 계산 표면 재료 표(`derived_from`), 읽는 API 주소(`routes`, 비어 있으면 "데이터 탐색 주소(/db/table)로 읽습니다"), 쓰는 화면(링크), 손 작업 표면 `manual_note`, 스크립트 `note` 가 있으면 함께.
  - 작업: 실행 시각(`schedule_kst`), 기준 시간(`stale_hours`), 단계 목록(이름·스크립트·기록 키·그 키의 마지막 결과).
  - 원천: 이름·주소(외부 링크)·이 원천을 받는 작업과 화면.
  - 화면: 제목(링크)·부르는 API 주소·읽는 표.
- 휴대폰(폭 640px 이하): 5칸을 위아래로 쌓고 선은 그리지 않습니다. 상자마다 "→ 이어지는 곳: …" 한 줄 목록을 둡니다. 누르기·상세 카드·요약 줄은 같습니다.
- 사이트 규칙: 정중체(습니다/합니다), 이모지·줄표(—) 없음, 숫자·점에 `data-tooltip`(정의·기준), 다크 모드.

## 3. 데이터 받기

| 무엇 | 주소 | 실패하면 |
|---|---|---|
| 계보 | `../data/table_lineage.json` | 그림을 그릴 수 없으므로 탭 안에 "계보 자료를 불러오지 못했습니다(이유)" 를 보입니다 |
| 행 수 | `/db/tables` (`tables[].name·rows`) | 점·행 수를 감추고 그림 위에 "운영 정보를 불러오지 못했습니다" 한 줄 |
| 실행 기록 | `/jobs/status` (`details[키] = {last_run_at, status, note}`) | 위와 같음 |

- 응답 이상(HTTP 오류, `error`·`detail` 필드, 빈 목록)은 가리지 않고 위 문구에 이유를 붙여 보입니다.
- 새 API 는 만들지 않습니다. Worker 배포도 하지 않습니다(`/db/tables` 의 한국어 설명은 Worker 재배포 전까지 비어 있으므로 설명은 계보 파일의 `desc` 를 씁니다).

## 4. 상태 판정

- 표의 기록 키: `written_by` 스크립트마다 `scripts[].status_keys`(작업 id → 기록 키)를 모읍니다. 키가 없는 스크립트(예: `sync_players_from_roster.py`)는 건너뜁니다. 키가 하나도 없는 수집·계산 표는 "기록 없음"입니다.
- 키 하나의 상태(그 키를 남기는 작업의 `stale_hours` 기준, 지금 시각과 비교):
  - 실패: `status` 가 `fail`
  - 기록 없음: `details[키]` 가 없음
  - 오래됨: `last_run_at` 이 `stale_hours` 시간보다 오래됨
  - 정상: `status` 가 `ok`·`skip` 이고 기준 시간 안
  - 그 밖의 `status` 값은 화면이 모르는 값이므로 "기록 없음"이 아니라 오래됨과 같은 회색으로 두고 문구에 그 값을 그대로 적습니다.
- 표의 상태 = 키 상태 중 가장 나쁜 것. 나쁜 순서: 실패 > 오래됨 > 기록 없음 > 정상.
- 작업 상자의 상태 = 그 작업 `steps[].status_key`(null 제외) 상태 중 가장 나쁜 것.
- `last_run_at` 은 "YYYY-MM-DD HH:MM" 한국 시각 글자입니다. 오래됨 판단은 한국 시각(UTC+9)으로 읽어 지금과 비교합니다.
- 점 문구 예:
  - 정상: "마지막 갱신 10/03 16:12 · roster · 성공"
  - 실패: "마지막 실행 실패 10/03 07:27 · daily · futures"
  - 오래됨: "36시간 넘게 갱신이 없습니다(기준: 매일 16:07 실행) · 마지막 10/01 16:10"
  - 기록 없음: "실행 기록이 아직 없습니다"
  - 손 작업: "손 작업으로 채운 표입니다: <manual_note>"
- 요약 줄 숫자: 손 작업·meta 를 뺀 표(지금 16개)를 상태별로 셉니다.

## 5. 경로 찾기

- 노드 id 는 계보 파일 그대로(`source:`·`job:`·`table:`·`page:`). page id 에 `/`·`.` 이 있어 DOM 에는 `data-id` 속성으로만 넣고 CSS 선택자로 쓰지 않습니다(쓸 때는 `CSS.escape`).
- 누른 노드에서 `edges` 를 따라 앞(from→to)으로, 뒤(to→from)로 각각 끝까지 갑니다(방문 표시로 반복 방지). 두 방향의 노드·선을 합쳐 강조합니다.
- 손 작업 표가 접혀 있으면 손 작업 표 노드를 모두 "손 작업 표" 묶음 노드 하나로 바꿔 계산합니다. 묶음을 누르면 펼침/접힘만 하고 강조는 바꾸지 않습니다. 펼친 뒤에는 개별 손 작업 표를 누를 수 있습니다.

## 6. 배치

- 칸 x 위치는 그림 폭을 5등분해 정합니다. 상자 폭은 칸 폭에서 여백을 뺀 값입니다(최소 150px, 그림이 그보다 좁으면 그림 영역을 가로로 밀어 볼 수 있게 함).
- 칸 안 순서: 원천·작업·화면은 계보 파일 순서(이름 순). 표 칸은 받아 온 표(이름 순) 다음에 손 작업 묶음(펼치면 손 작업 표 이름 순). 계산 표는 이름 순.
- 상자 높이·간격은 고정이고, 그림 높이는 가장 긴 칸에 맞춥니다.
- 선은 왼쪽 상자의 오른쪽 가운데에서 오른쪽 상자의 왼쪽 가운데로 가는 3차 곡선입니다.

## 8. 검증

- Node(저장소 밖 `C:/tmp/bstats-team-stats-check/tests/`): 픽스처 = 지금 `table_lineage.json` + `/jobs/status`·`/db/tables` 를 한 번 받아 저장한 것.
  1. 키 상태: 실패·오래됨(경계 포함)·기록 없음·정상·건너뜀·모르는 값
  2. 표 상태 = 가장 나쁜 것, 키 없는 스크립트 건너뜀
  3. 작업 상태, 요약 숫자(손 작업 11 따로, 상태별 합 = 16)
  4. 경로: `table:games` 를 누르면 `job:daily`·원천·`games` 를 읽는 계산 표·화면이 나오고 상관없는 표는 안 나옴

  6. 배치: 같은 칸 상자가 겹치지 않음, 5칸 x 순서
  7. 화면 이름 꼬리 떼기, meta·explorer 숨김
- 화면 캡처(헤드리스 Edge, 바탕화면 PNG): 처음 화면, `games` 누름, 요약 '실패' 누름, 손 작업 펼침, 다크 모드, 휴대폰 390px(CDP), 기존 데이터 탐색·사이트맵 탭 그대로·`#sitemap` 바로 열림.
